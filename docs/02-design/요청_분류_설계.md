# 요청 분류 설계

## 1. 목적

요청 분류는 한 번의 질문에서 어떤 도구를 열지 정하는 단계다.

최종 구현 목표에서 사용자에게 노출되는 실행 모드는 로컬 모드 하나다. 요청 분류는 실행 모드를 바꾸지 않고, 작업공간 도구만 사용할지 엔진 소스 참고 도구까지 함께 사용할지를 결정한다.

코드 기준 분류기는 자연어 점수 모델을 호출하지 않는다. 작업공간 경로와 `엔진 관련 질문` 선택값을 기준으로 `local` 또는 `source`를 만들고 있다. 이 문서는 그 코드 기준을 확인한 뒤, 시스템 전체 흐름 설계에 맞춘 최종 목표 구조를 함께 정의한다.

## 2. 입력 값

| 입력 | 의미 |
| --- | --- |
| `prompt` | 사용자 질문 |
| `workspacePath` | 선택된 작업공간 경로 |
| `selectedFilePath` | 화면에서 선택한 작업공간 파일 |
| `engineQuestionOverride` | 화면의 `엔진 관련 질문` 체크값 |

## 3. 코드 기준 분류 결과

코드 기준 요청 문맥은 아래 구조로 만들어진다.

```json
{
  "prompt": "사용자 질문",
  "workspacePath": "사용자 작업공간 경로",
  "selectedFilePath": "선택 파일",
  "explicitPaths": [],
  "engineQuestionOverride": false,
  "mode": "local",
  "initialToolNames": [
    "list_files",
    "glob",
    "grep",
    "find_symbol",
    "find_callers",
    "find_references",
    "lsp",
    "read_symbol_span",
    "symbol_outline",
    "symbol_neighborhood",
    "read_file",
    "edit"
  ]
}
```

| 값 | 코드 기준 의미 |
| --- | --- |
| `mode` | `local`이면 Qwen Agent Python 실행기, `source`이면 백엔드 직접 엔진 답변 경로로 실행한다. |
| `explicitPaths` | 질문에서 찾은 작업공간 상대 경로 목록이다. |
| `selectedFilePath` | `local`에서만 유지한다. |
| `initialToolNames` | `local`에서 모델에 제공할 작업공간 도구 목록이다. |

코드 기준 모드 결정은 아래와 같다.

| 조건 | 코드 기준 결과 |
| --- | --- |
| `engineQuestionOverride`가 `true` | `source` |
| `engineQuestionOverride`가 `false`이고 작업공간이 있음 | `local` |
| `engineQuestionOverride`가 `false`이고 작업공간이 없음 | `source` |
| `engineQuestionOverride`가 없고 작업공간이 있음 | `local` |
| `engineQuestionOverride`가 없고 작업공간이 없음 | `source` |

`source`에서는 작업공간 경로가 있어도 `selectedFilePath`와 `explicitPaths`를 비운다. 백엔드 직접 엔진 답변 경로가 회사 엔진 소스만 기준으로 답하기 때문이다.

## 4. 최종 목표 분류 결과

최종 목표에서 분류 결과는 실행 모드가 아니라 도구 범위다.

```json
{
  "executionMode": "local",
  "workspacePath": "사용자 작업공간 경로",
  "selectedFilePath": "선택 파일",
  "explicitPaths": [],
  "engineReference": {
    "enabled": true,
    "reason": "엔진 API 의미와 사용 예시 확인 필요"
  },
  "initialToolNames": [
    "list_files",
    "glob",
    "grep",
    "find_symbol",
    "find_callers",
    "find_references",
    "lsp",
    "read_symbol_span",
    "symbol_outline",
    "symbol_neighborhood",
    "read_file",
    "edit",
    "source_overview",
    "source_search",
    "source_read",
    "source_type_graph",
    "source_usages"
  ]
}
```

| 값 | 최종 목표 의미 |
| --- | --- |
| `executionMode` | 사용자 질문 실행은 `local` 하나로 고정한다. |
| `engineReference.enabled` | 엔진 소스 참고 도구를 함께 열지 나타낸다. |
| `engineReference.reason` | 엔진 참고를 켠 판단 이유다. |
| `initialToolNames` | 작업공간 도구와 필요한 엔진 참고 도구를 함께 담는다. |

## 5. 엔진 참고 판단 규칙

엔진 참고 판단은 체크값을 우선하고, 질문 내용 규칙을 보조로 사용한다. 점수 계산이나 별도 분류 모델은 쓰지 않는다.

| 조건 | 엔진 참고 |
| --- | --- |
| `엔진 관련 질문` 체크 | 켬 |
| 엔진 타입, 클래스, 함수, API 사용법 질문 | 켬 |
| 엔진 API 호출 예제나 사용처 요청 | 켬 |
| 선택 코드가 엔진 API를 어떻게 쓰는지 묻는 질문 | 켬 |
| 타입 관계, 상속, 입출력 타입, 이벤트 선언 질문 | 켬 |
| 작업공간 구조, 파일 설명, 단순 검색 | 끔 |
| 작업공간 파일 수정 요청 | 기본 끔 |

작업공간 파일 수정 요청이라도 수정 대상 코드가 엔진 API 사용법을 확인해야 하면 엔진 참고를 함께 켠다. 이때 수정 대상은 작업공간 파일이고, 엔진 소스는 설명과 검증용 참고 근거로만 사용한다.

## 6. 경로 추출 규칙

분류기는 사용자 질문에서 파일 경로처럼 보이는 값을 추출한다.

| 처리 | 설명 |
| --- | --- |
| 절대 경로 | 작업공간 안에 있으면 작업공간 상대 경로로 바꾼다. |
| 상대 경로 | `../` 밖으로 나가는 경로는 버린다. |
| URL | `http://`, `file://` 같은 값은 경로 후보에서 제외한다. |
| 중복 제거 | 대소문자를 무시해 같은 경로를 한 번만 남긴다. |
| 엔진 참고 사용 | 작업공간 경로 후보를 유지하고, 엔진 참고 도구는 별도 소스 경로를 조회한다. |

최종 목표에서는 엔진 참고를 켜도 `selectedFilePath`와 `explicitPaths`를 비우지 않는다. 선택 파일과 질문 속 경로는 사용자 작업공간 근거를 잡는 데 계속 필요하다.

## 7. 도구 범위

| 범위 | 제공 도구 |
| --- | --- |
| 작업공간 기본 도구 | `list_files`, `glob`, `grep`, `find_symbol`, `find_callers`, `find_references`, `lsp`, `read_symbol_span`, `symbol_outline`, `symbol_neighborhood`, `read_file`, `edit` |
| 엔진 핵심 참고 도구 | `source_search`, `source_read`, `source_type_graph`, `source_usages` |
| 엔진 넓은 조회 도구 | `source_overview`, `source_ls`, `source_glob` |

엔진 핵심 참고 도구는 API 의미, 사용 예시, 타입 관계 질문에 사용한다. 엔진 넓은 조회 도구는 전체 구조, 모듈, 폴더, 파일 목록 질문에서 함께 연다.

`source_grep` 실행 분기는 백엔드 서비스에 있지만 모델 도구 목록에는 포함하지 않는다. 텍스트 검색이 필요하면 통합 검색 또는 HTTP `/grep` 조회 결과를 엔진 참고 도구 내부 요약으로 사용한다.

## 8. 화면 값과 연결

| 화면 상태 | 최종 목표 요청 값 |
| --- | --- |
| 작업공간 선택됨, `엔진 관련 질문` 해제 | `executionMode: local`, `engineReference.enabled: false` |
| 작업공간 선택됨, `엔진 관련 질문` 체크 | `executionMode: local`, `engineReference.enabled: true` |
| 작업공간 선택됨, 질문 내용이 엔진 API 의미를 요구 | `executionMode: local`, `engineReference.enabled: true` |

화면 설정의 `engineQuestionDefault`는 `엔진 관련 질문` 체크박스의 기본값으로 저장된다.

## 9. 초기 문서에서 바뀐 점

초기 `에이전트 상세 설계`의 라우팅은 문서 질의, 코드 질의, 비교, 수정 같은 큰 작업 유형을 나누는 방식이었다.

이 문서는 시스템 전체 흐름 설계에 맞춰, 요청 분류를 로컬 모드 안의 도구 범위 결정으로 수정했다.

| 초기 문서 내용 | 이 문서에서의 수정 |
| --- | --- |
| 라우터가 작업 유형별 에이전트를 선택 | 로컬 모드 안에서 작업공간 도구와 엔진 참고 도구 범위 결정 |
| 문서 AI로 사내 문서 질의를 분기 | 문서 질의 분기 제거 |
| RAG 검색 경로를 문서 답변에 사용 | 엔진 소스 참고 도구가 코드 근거를 조회 |
| 문서 질의와 코드 질의를 분리 | 작업공간 근거와 엔진 근거를 같은 질문 실행 안에서 사용 |
| 분류 결과가 복잡한 작업 그래프를 선택 | 분류 결과가 엔진 참고 필요 여부와 도구 목록을 결정 |

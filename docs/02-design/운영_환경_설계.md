# 운영 환경 설계

## 1. 실행 구성

| 구성 | 역할 |
| --- | --- |
| 데스크톱 앱 | 사용자 화면, 작업공간 도구 실행, 세션 저장, Qwen Agent Python 실행기 실행 |
| 백엔드 API | 엔진 소스 조회, 색인, 소스 읽기 기능 제공 |
| 사용자 작업공간 | 로컬 작업공간 도구의 분석과 수정 대상 |
| 엔진 소스 | 백엔드 소스 서비스가 읽는 회사 엔진 코드 |
| 사용자 데이터 | 데스크톱 설정, 세션, 실행 상태, Qwen Agent Python 실행기 파일 |
| 모델 서버 | OpenAI 호환 채팅 완료 API 제공 |

## 2. 핵심 설정

실행 기본값:

| 값 | 기본값 |
| --- | --- |
| 백엔드 API 주소 | `http://192.168.2.238:8000/api` |
| 백엔드 API 접두 경로 | `/api/v1` |
| 모델 서버 주소 | `http://192.168.2.212:8000/v1` |

모델 이름은 별도로 설정하지 않는다. LLM 서버에 모델이 하나만 떠 있으면
요청의 `model` 필드를 비워도 그 모델로 응답하므로, 데스크톱/백엔드 모두
모델명을 관리하지 않는다. (과거에 있었던 워크플로 재작성 전용 모델
서버 설정도 그 기능 제거와 함께 없어졌다.)

데스크톱 설정 JSON은 아래 키를 가진다.

```json
{
  "serverBaseUrl": "http://192.168.2.238:8000/api",
  "llmBaseUrl": "http://192.168.2.212:8000/v1",
  "workspacePath": "사용자 작업공간 경로",
  "engineQuestionDefault": true,
  "recentWorkspaces": []
}
```

엔진 소스 경로와 색인 저장 경로는 데스크톱 설정에 저장하지 않는다. 백엔드 환경값으로 관리한다.

| 백엔드 환경값 | 기본값 | 역할 |
| --- | --- | --- |
| `PIXLLM_API_PREFIX` | `/api/v1` | 백엔드 API 접두 경로 |
| `PIXLLM_SOURCE_DATA_DIR` | `.profiles` | 백엔드 소스 데이터 기준 폴더 |
| `RAW_SOURCE_ROOT` | `.profiles/raw_source/source` | 엔진 원본 소스 루트 |
| `SOURCE_RUNTIME_DIR` | `.profiles/source` | 메서드 색인과 소스 명세 저장 경로 |
| `PIXLLM_LLM_BASE_URL` | `http://192.168.2.212:8000/v1` | 백엔드 직접 답변 경로의 모델 서버 주소 |

## 3. 사용자 데이터 저장

데스크톱은 사용자 홈 아래 `.pixllm/desktop` 폴더에 JSON 파일을 저장한다.

| 데이터 | 저장 위치 | 저장 내용 |
| --- | --- | --- |
| 설정 | `settings.json` | 백엔드 API 주소, 모델 서버 주소, 작업공간, 엔진 질문 기본값, 최근 작업공간 |
| 세션 | `sessions/index.json`, `sessions/items/*.json` | 대화 메시지, 제목, 생성/수정 시각, 실행 로그 |
| 실행 상태 | `agent-runtime/*.json`, `agent-runtime/index.json` | 요청별 메시지, 실행 추적, 대화 실행 기록, 파일 읽기 캐시 |
| Qwen Agent Python 실행기 | `qwen-agent-sidecar` | 패키징 환경에서 꺼낸 Python 실행기 파일 |

세션 상태는 `sessionId`와 `workspacePath`를 묶은 해시 키로 저장한다. 같은 작업공간에서 같은 세션을 다시 열면 이전 대화와 실행 추적을 복원한다.

## 4. 데스크톱 실행

| 방식 | 명령 | 설명 |
| --- | --- | --- |
| 개발 실행 | `npm run dev` | Vite 개발 서버를 `127.0.0.1:4173`에서 띄우고 Electron을 실행한다. |
| 빌드 | `npm run build` | 렌더러를 빌드하고 배포 HTML을 정리한다. |
| 포터블 빌드 | `npm run dist:portable` | Windows 포터블 실행 파일을 만든다. |
| 화면 검사 | `npm run check` | Svelte 타입 검사를 실행한다. |

데스크톱 실행에 필요한 Qwen Agent Python 의존성은 `qwen-agent==0.0.34`, `soundfile>=0.13.1`이다. 앱은 Python 후보를 찾고, 필요한 경우 묶인 요구 파일로 설치를 시도한다.

## 5. 백엔드 API

백엔드 API는 FastAPI 앱이다. 기본 라우터는 상태 확인과 소스 조회로 구성된다.

| 항목 | 값 |
| --- | --- |
| 기본 주소 | `http://192.168.2.238:8000/api` |
| 실제 API 접두 경로 | `/api/v1` |
| 응답 형식 | `{ "ok": true, "data": ..., "error": null }` |
| 상태 확인 | `/api/v1/health`, `/api/v1/health/live`, `/api/v1/health/ready` |

주요 소스 호출:

| 기능 | 데스크톱 요청 경로 | 실제 백엔드 경로 |
| --- | --- | --- |
| 엔진 개요 | `/v1/source/context` | `/api/v1/source/context` |
| 엔진 색인 다시 만들기 | `/v1/source/index/rebuild` | `/api/v1/source/index/rebuild` |
| 엔진 파일 목록 | `/v1/source/ls` | `/api/v1/source/ls` |
| 엔진 파일 찾기 | `/v1/source/glob` | `/api/v1/source/glob` |
| 엔진 텍스트 검색 | `/v1/source/grep` | `/api/v1/source/grep` |
| 엔진 심볼 검색 | `/v1/source/symbols` | `/api/v1/source/symbols` |
| 엔진 타입 관계 | `/v1/source/type-graph` | `/api/v1/source/type-graph` |
| 엔진 사용처 검색 | `/v1/source/usages` | `/api/v1/source/usages` |
| 엔진 통합 검색 | `/v1/source/search` | `/api/v1/source/search` |
| 엔진 소스 읽기 | `/v1/source/read` | `/api/v1/source/read` |
| 코드 기준 직접 답변 | `/v1/source/answer` | `/api/v1/source/answer` |

데스크톱 기본 백엔드 주소가 `/api`로 끝나기 때문에 `/v1/...` 요청 경로를 붙이면 실제 주소는 `/api/v1/...`이 된다. 백엔드 주소가 이미 `/api/v1`로 끝나는 경우에는 중복되지 않게 결합한다. 최종 목표의 질문 실행은 `/v1/source/answer`를 사용자 답변 경로로 쓰지 않고, 엔진 조회 경로를 엔진 참고 도구 내부에서 사용한다.

## 6. 백엔드 실행

백엔드는 Docker 구성을 제공한다.

| 파일 | 역할 |
| --- | --- |
| `Dockerfile.agent` | Python 3.11 기반 백엔드 이미지 빌드 |
| `docker-compose.yml` | `pixllm-source-api` 컨테이너 실행 |
| `requirements-agent.txt` | FastAPI, Uvicorn, Pydantic, PyYAML, NumPy, soundfile 등 백엔드 의존성 |
| `.env.example` | 로컬 실행용 환경값 예시 |
| `.env.compose.example` | Docker Compose 실행용 환경값 예시 |

Compose 기준 백엔드는 컨테이너의 `8000` 포트를 호스트 `AGENT_API_HOST_PORT`로 노출한다. 기본 호스트 포트는 `8000`이다.

## 7. 엔진 색인 실행

엔진 색인 실행기는 백엔드 Python 소스 서비스에 있다.

| 단계 | 처리 |
| --- | --- |
| 경로 확인 | `RAW_SOURCE_ROOT`가 가리키는 엔진 소스 경로를 기준으로 한다. |
| 파일 수집 | 엔진 소스 확장자 목록으로 대상 파일을 모은다. |
| 선언 추출 | 공개 타입과 멤버 선언을 색인한다. |
| 사용처 후보 | 구현 파일에서 심볼 문자열과 `타입::메서드` 패턴을 찾는다. |
| JSON 저장 | 메서드 색인과 소스 명세를 `SOURCE_RUNTIME_DIR`에 저장한다. |
| 조회 반영 | 소스 API가 저장된 색인과 원본 소스 범위를 읽는다. |

색인 생성은 `/api/v1/source/index/rebuild` 호출로 실행한다. 질문 실행 중에는 저장된 색인을 읽고 필요한 경우 원본 소스 범위만 추가로 읽는다.

## 8. 모델 서버

모델 서버는 OpenAI 호환 채팅 완료 API를 제공한다.

| 항목 | 설명 |
| --- | --- |
| 기본 주소 | `http://192.168.2.212:8000/v1` |
| 모델 이름 | 요청에 전달하지 않음 — 서버에 모델이 하나만 떠 있으면 비워도 그 모델로 응답 |
| 채팅 완료 | `/chat/completions` |
| 도구 호출 | 모델이 작업공간 도구나 엔진 참고 도구를 호출할 때 사용 |

## 9. 구성 범위

본 설계의 운영 단위는 데스크톱 앱, 백엔드 API, 사용자 작업공간, 엔진 소스, 사용자 데이터, 모델 서버다.

초기 문서 AI/RAG 운영 구성에 있던 문서 벡터 저장소, 문서 수집 작업, GraphRAG 운영 구성은 본 설계의 운영 단위에 포함하지 않는다.

## 10. 초기 문서에서 바뀐 점

초기 `인프라 상세 설계`는 벡터 저장소, 그래프 저장소, 캐시, 오브젝트 저장소, 배치 실행 구성을 넓게 다뤘다.

본 문서는 데스크톱 실행에 필요한 값과 백엔드 소스 API 환경값 중심으로 수정했다.

| 초기 문서 내용 | 본 문서에서의 수정 |
| --- | --- |
| 여러 서버 저장소 묶음 | 데스크톱 앱, 백엔드 API, 작업공간, 엔진 소스, 모델 서버로 축소 |
| 문서 AI용 지식 베이스와 벡터 저장소 | 본 운영 구성에 포함하지 않음 |
| 문서/코드 데이터 파이프라인 | 백엔드 엔진 소스 루트와 색인 경로 설정으로 정리 |
| 중앙 저장소와 배치 작업 | 사용자별 설정과 세션 저장 중심 |
| 대규모 운영 토폴로지 | 데스크톱 앱과 백엔드 소스 API 중심 |

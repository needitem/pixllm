# 근거 기록 설계

## 1. 목적

근거 기록은 모델이 어떤 정보를 보고 답했는지, 어떤 도구를 실행했는지, 파일을 수정했다면 어떤 차이가 생겼는지를 화면과 세션에 남기기 위한 구조다.

최종 목표에서 근거 기록은 로컬 모드 하나의 실행 로그 안에 남는다. 작업공간 근거와 엔진 근거는 같은 질문 실행 안에서 함께 기록하되, 출처와 역할은 구분한다.

코드 기준으로는 작업공간 실행과 백엔드 직접 엔진 답변 실행이 분리되어 있다. 최종 목표에서는 백엔드 소스 조회 결과를 엔진 참고 도구의 관측값으로 기록한다.

## 2. 기록 대상

| 기록 | 내용 | 표시 위치 |
| --- | --- | --- |
| 대화 메시지 | 사용자 질문과 최종 답변 | 대화 영역 |
| 실행 시작 | 요청 식별자, 작업공간, 선택 파일, 엔진 참고 여부 | 실행 로그 |
| 상태 변화 | 준비, 모델 호출, 도구 실행, 완료, 오류 | 실행 로그 |
| 작업공간 도구 추적 | 작업공간 도구 이름, 입력, 관측 결과 | 실행 로그 |
| 엔진 참고 도구 추적 | 엔진 소스 조회 도구 이름, 입력, 관측 결과 | 실행 로그 |
| 작업공간 근거 | 사용자 코드에서 확인한 파일, 줄, 심볼 | 실행 로그와 최종 답변 |
| 엔진 근거 | 엔진 소스에서 확인한 선언, 사용 예시, 타입 관계 | 실행 로그와 최종 답변 |
| 수정 차이 | 수정 전후 줄 단위 차이 | 실행 로그, 세션 |
| 사용량 | 도구 호출 수와 모델 호출 사용량 | 실행 요약 |

## 3. 실행 로그 알림

데스크톱 실행부는 화면으로 실행 로그 알림을 보낸다. 알림 이름은 아래 범위를 사용한다.

| 알림 | 의미 |
| --- | --- |
| `request_start` | 요청 실행이 시작됨 |
| `session_restored` | 기존 세션 문맥을 불러옴 |
| `status` | 실행 상태 문구 |
| `model` | 모델 실행 단계 알림 |
| `assistant_message` | 모델 답변 조각 |
| `tool_batch_start` / `tool_batch_end` | 도구 호출 묶음 시작/종료 |
| `tool_use` | 도구 호출 입력 |
| `tool_result` | 도구 실행 결과 |
| `transition` | 실행 단계 전환 |
| `terminal` | 종료 사유 |
| `token` | 토큰 단위 출력 |
| `done` | 정상 완료 |
| `cancelled` | 취소됨 |
| `error` | 오류 발생 |

## 4. 작업공간 도구 추적

작업공간 도구 추적 항목은 Qwen Agent Python 실행기의 도구 호출 단위로 만들어진다.

```json
{
  "round": 1,
  "thought": "qwen-agent function call",
  "tool": "grep",
  "toolUseId": "toolu_qwen_agent_1",
  "input": {
    "query": "NXImageView",
    "limit": 20
  },
  "observation": {
    "ok": true,
    "query": "NXImageView",
    "total": 3,
    "items": []
  }
}
```

작업공간 파일 읽기 결과는 줄 범위를 `lineRange`로 남긴다.

```json
{
  "ok": true,
  "path": "src/example.cpp",
  "lineRange": "1-80",
  "content": "줄 번호가 붙은 파일 내용"
}
```

파일 수정 결과는 수정 차이와 변경량을 함께 남긴다.

```json
{
  "ok": true,
  "path": "src/example.cpp",
  "occurrences": 1,
  "replace_all": false,
  "added": 2,
  "removed": 1,
  "diff": "줄 단위 차이",
  "diff_truncated": false
}
```

## 5. 엔진 참고 도구 추적

엔진 참고 도구도 작업공간 도구와 같은 실행 추적 구조를 사용한다. 차이는 관측 결과가 백엔드 소스 API에서 온다는 점이다.

```json
{
  "round": 1,
  "thought": "qwen-agent function call",
  "tool": "source_search",
  "toolUseId": "toolu_qwen_agent_2",
  "input": {
    "query": "NXImageView",
    "limit": 8
  },
  "observation": {
    "ok": true,
    "query": "NXImageView",
    "candidates": [],
    "read_targets": [],
    "source_spans": []
  }
}
```

엔진 소스 파일 읽기 결과는 줄 범위를 `line_range`로 남긴다.

```json
{
  "ok": true,
  "source_id": "raw",
  "path": "Source/example.h",
  "kind": "source_file",
  "line_range": "1-120",
  "content": "줄 번호가 붙은 소스 내용"
}
```

엔진 참고 도구는 도구 관측에서 필요한 항목을 모델 재입력용 요약으로 줄인다. 주요 항목은 API 서명, C# 호출 제약, 타입 관계, 이벤트 선언, 추천 읽기 대상, 주변 소스다.

## 6. 모델 재입력용 요약

모델에 다시 넣는 근거는 별도 JSON 문서로 저장하지 않는다. 도구별 관측 결과를 짧은 문자열로 요약해 다음 모델 호출 또는 최종 답변 작성에 사용한다.

| 도구 결과 | 요약 방식 |
| --- | --- |
| 작업공간 파일 목록 | 경로 목록과 개수 |
| 작업공간 텍스트 검색 | 경로, 줄 번호, 일치 줄 |
| 작업공간 파일 읽기 | 필요한 범위의 내용 |
| 작업공간 심볼 읽기 | 심볼 본문과 줄 범위 |
| 파일 수정 | 추가/삭제 줄 수와 차이 요약 |
| 엔진 통합 검색 | 선언 후보, 파일 후보, 추천 읽기 대상 |
| 엔진 타입 관계 | 관련 타입, 멤버, 연결 이유 |
| 엔진 사용처 검색 | 사용 위치와 주변 줄 |

## 7. 작업공간 근거와 엔진 근거

| 구분 | 작업공간 근거 | 엔진 근거 |
| --- | --- | --- |
| 실행 위치 | 로컬 질문 실행 안의 작업공간 도구 | 로컬 질문 실행 안의 엔진 참고 도구 |
| 역할 | 사용자가 다루는 코드 설명/수정 | 엔진 API 의미와 활용법 확인 |
| 경로 기준 | 선택된 작업공간 | 백엔드 `RAW_SOURCE_ROOT` |
| 줄 범위 필드 | `lineRange` | `line_range` |
| 답변 표현 | 선택된 코드에서 확인한 내용 | 참고한 선언과 사용 예시 |
| 수정 차이 | 기록 가능 | 없음 |

## 8. 세션 저장

세션은 사용자 데이터 폴더 아래 JSON 파일로 저장된다.

| 저장 항목 | 경로 |
| --- | --- |
| 세션 목록 | `sessions/index.json` |
| 세션 항목 | `sessions/items/*.json` |
| 실행 상태 | `agent-runtime/*.json` |
| 실행 상태 목록 | `agent-runtime/index.json` |

세션에는 대화 메시지, 엔진 참고 여부, 도구 추적, 최종 답변, 수정 차이, 사용량 요약이 포함된다.

## 9. 초기 문서에서 바뀐 점

초기 문서의 기록 구조는 백엔드 API 응답, 검색 결과, 에이전트 상태를 각각 다루는 형태였다.

이 문서는 사용자가 화면에서 확인하는 실행 로그와 세션 기록 중심으로 수정했다.

| 초기 문서 내용 | 이 문서에서의 수정 |
| --- | --- |
| 백엔드 검색 결과와 에이전트 상태가 분리 | 한 요청의 실행 로그와 세션 기록으로 통합 |
| 문서/코드 검색 근거가 별도 경로로 관리 | 작업공간 근거와 엔진 근거를 같은 실행 안에서 출처만 구분 |
| 답변 결과 중심 기록 | 도구 호출, 관측 결과, 수정 차이까지 기록 |
| 문서 RAG 근거 조각 중심 | 작업공간 파일과 엔진 소스 도구 결과 중심 |
